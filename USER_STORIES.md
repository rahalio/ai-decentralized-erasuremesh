# Erasuremesh — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Data protection officer

- As a DPO, I want an erasure order to fan out to every processor on the graph, so that cascade liability is operational not theoretical.
- As a DPO, I want derived personas flagged before closure, so that Lori-Smith style residue cannot be marked compliant.
- As a DPO, I want an evidence pack suitable for a supervisory authority, so that I can demonstrate process under audit.

### Privacy operations analyst

- As a privacy analyst, I want to log verbal and written forget requests into one queue, so that channel does not determine whether rights are honoured.
- As a privacy analyst, I want SLA countdowns and extension records, so that month-end surprises are visible early.
- As a privacy analyst, I want to mark disproportionate-effort exceptions with rationale, so that recipient-notice failures are auditable.

### Vendor / processor manager

- As a vendor manager, I want processors to acknowledge erasure via API, so that email trails are not the system of record.
- As a vendor manager, I want overdue acknowledgements escalated, so that weak links in the supply chain surface before fines.

### Product engineer (derived models)

- As a product engineer, I want a list of derived artefacts tied to a subject pseudonym, so that I know what model assets to scrub.
- As a product engineer, I want to block release of a segment refresh if an open erasure touches its training cohort, so that we do not re-materialise forgotten subjects.

### Platform administrator

- As a platform administrator, I want dual control to force-close an order with a failed node, so that emergency closures cannot be unilateral.
- As a platform administrator, I want tenant-scoped erasure for multi-tenant products, so that one customer’s request cannot delete another’s data.
